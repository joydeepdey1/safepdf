# Phase 6 Verification Tests (Polish & Deploy)

Please execute the following manual tests to verify the overall polish, performance, navigation, accessibility, and production readiness of PaperVault:

### 1. Homepage Navigation & Directory
- Open `http://localhost:5173/`.
- Verify the hero section displays cleanly with title and call-to-actions.
- Click the filter tabs:
  - **All Tools**: Shows 8 tools.
  - **PDF Tools**: Shows 5 tools (Merge, Split, Rotate, Delete Pages, Images to PDF).
  - **Image Tools**: Shows 3 tools (Compress, Resize, Convert).
- Click "Launch tool" or any card to ensure it navigates directly to that tool route.

### 2. Header & Breadcrumb Flow
- While viewing any tool (e.g. `http://localhost:5173/pdf/merge` or `http://localhost:5173/image/resize`), verify the header displays the "← All Tools" button.
- Click "← All Tools" and verify it brings you back to `/#tools` on the homepage.
- Click the brand logo ("PaperVault") and confirm it returns to `/`.
- Verify the header links ("Tools", "Privacy", GitHub icon) function correctly.

### 3. Asynchronous Lazy Loading
- Open DevTools -> Network -> JS.
- Navigate to the homepage, clear network logs, and then click on an unvisited tool (e.g., "Rotate PDF").
- Verify that a dedicated chunk (e.g., `rotate-*.js`) is dynamically loaded on demand, and that the fallback spinner/text briefly renders if network is throttled.

### 4. Accessibility & Keyboard Navigation
- Use `Tab` key to navigate across the page.
- Ensure focus rings (`focus-visible:ring-blue-500`) are prominently visible on all interactive cards, links, and buttons.
- Tab into the Dropzone and press `Enter` or `Space`: verify the native file picker opens without needing a mouse click.

### 5. Mobile & Responsive Layout
- Open DevTools Responsive Mode and switch to mobile viewport (375px - 425px).
- Verify tool cards, header, dropzone, and action bars stack naturally with no horizontal scrollbars or clipped text.

### 6. Automated Pipeline Verification
- In your terminal, run `npm run test` (all 11 tests pass).
- Run `npm run lint` (0 errors, 0 warnings).
- Run `npm run build` (production build succeeds with code splitting).
